# P5 asynchronous lifecycle preparation — 26 October 2026

This is offline developer preparation, not a live voice implementation or device acceptance. Participant AI and voice remain off. No application route imports the new controller. A browser capture adapter is prepared but is not imported by an application route. No live provider adapter, approval grant, paid connection or model choice is introduced.

`service/voice-lifecycle.ts` coordinates injected admission, capture, connection and playback resources around the existing `MockVoiceLifecycle` transcript/segment model. The shared conversation service remains the only context and source authority; the controller neither builds provider requests nor changes saved conversation content.

The controller requires deliberate start or explicit Resume, revalidates admission before connection and activation, and preserves independent closure evidence for four resources. Pause remains unconfirmed while acquisition is pending, even if an AbortSignal was sent. Late handles are closed; failed handles remain reachable for an explicit cleanup retry. Resume cannot create another session until the previous resources and pending input changes are settled. Network recovery does not reconnect. Connection-loss events are bound to their exact attempt identity and cannot close a resumed session or change an intentional Finish talking into Pause. Type instead and Finish talking close resources while retaining the thread identity for the existing text service.

Mute changes input only. Stop answer, interruption and preference-off invalidate old output through the existing model, cancel pending shared-service work through a supplied callback, and request playback/queue cancellation. A failed playback stop closes the session. Played segments remain distinguishable from unheard cancelled segments. Private-practice assurance is available only after confirmed Pause and complete cleanup.

The port contracts require initially suppressed capture; explicit terminal resource closure; independent playback and connection cleanup; and a server-owned revalidatable admission lease. An adapter that throws during partial acquisition must clean those resources itself or return their handles for controller cleanup. An unavailable capture may carry a partial handle. Admission must not itself open a paid connection. Production wiring must retain separately approved budgets, identity, expiry, dispatch accounting and provider termination evidence; this module supplies none of that authority.

The browser adapter uses an explicitly supplied secure-context/mediaDevices environment and requests audio without video only when invoked. It initially disables input, retains ownership of tracks removed from the stream, distinguishes input suppression from track termination, checks ended state after stopping, and retains failed handles for retry. An unresolved browser permission request is not treated as cancelled merely because its AbortSignal fired. It performs no recording, storage, transcription or provider request. API basis: [W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/), including track stop semantics, mutable stream membership and unresolved permission requests. Physical microphone state is not inferred from mocked browser objects.

Initial checkpoint evidence (superseded by the follow-up below): 30 controller and 18 browser-capture behavioral tests covering denied/dismissed/unavailable permission, revoked/expired admission, late admission/capture/connection completion, pending and failed shutdown, cleanup retry, mute/Stop/Pause distinction, explicit Resume, thread switching, Type instead, output cancellation, cancellation callback failure, and fulfilled/rejected late input-enabling races. The final execution results and source hashes are recorded in `artifacts/conversation-eval/offline-validation-v3/verification.json`. Full strict TypeScript and ESLint for all four new code/test files passed. The complete regression run passed all 1,916 tests across 107 files with one worker and a 60-second outer test allowance; provider deadlines and legacy inner subprocess deadlines were not changed. These tests use injected doubles and cannot establish physical microphone state, actual audio heard, provider billing cessation, assistive-technology behavior or arbitrary-language response quality.

## Shared-service binding and UI follow-up — 26 October 2026

`service/voice-service-binding.ts` now coordinates the controller with the exact `ConversationService.voice` model using injected offline resource ports. It maps store IDs explicitly to internal thread IDs and keeps the selected record separate from the resource-owning attempt. `getThreadLifecycleBinding()` exposes a read-only record/epoch fence; it is not an authentication or provider grant. No application route imports the binding, controller or capture adapter.

Stop fences pending typed work before, during and after a voice attempt. Pause, Finish talking, Type instead, preference-off, switching, Delete, Discard, Clear and disposal retain resource ownership until confirmed cleanup. Delete and Clear invalidate content synchronously even while resource acquisition is unresolved. Late results cannot activate a deleted or recreated record. Newer same-thread selection defeats older pending navigation, old connection events cannot affect a later attempt, and a disposed coordinator cannot modify a new owner. Direct legacy service calls do not themselves close real resources: future integration must use the coordinator and reconcile external invalidation.

An unconfirmed service cancellation now remains visible in every public lifecycle snapshot and blocks restart, rebinding, ownership release and private-practice assurance. Another Stop does not silently retry it; explicit cleanup retry is required. The controller also revalidates admission after initial input enabling, closing a deletion/expiry race before activation. An explicit retry can synchronously fence the same record twice when both selected-work and controller holds exist; this does not acquire a resource or imply exact-once cancellation.

The existing preview and staging interfaces restore focus to a surviving opener or stable fallback when dialogs close. Staging destructive confirmations initially focus Cancel. Preview rename distinguishes an empty name from a simulated save failure, associates the error with its input and preserves the saved title on failure. Pending replies do not block deliberate Delete.

## Controlled voice UI and session contract — 27 October 2026

`VoiceControls.tsx` and the pure `service/voice-controls.ts` presentation model now prepare Start, Mute/Unmute, Stop answer, Pause, Resume, Finish talking, Type instead and explicit Retry. They remain inactive: no application route imports them. The component consumes the coordinator's snapshot and sends action intents to a host; it never opens a device or provider connection. The host must invoke the coordinator synchronously, publish its snapshot and pending-command metadata immediately, then publish again on settlement. Host promises are not evidence of confirmed microphone state or cleanup.

The controller now exposes authoritative `inputChangePending`. During a pending input change the UI does not claim that the microphone is confirmed muted. Mute remains available while a playback Stop is pending, and shutdown actions remain available during setup. Private-practice assurance requires the current selected attempt, confirmed Pause and complete cleanup. Failed cancellation/closure remains visible until explicit retry; switching records cannot expose the retained old attempt's Resume. Cleaned-up input/setup failures retain an explanation rather than appearing as an ordinary Finish.

Active unmute now revalidates admission after capture input changes, as initial activation already did. Five new regressions first failed against the prior implementation and then passed: pending Mute/Unmute visibility, admission expiry during active unmute, and external Delete/Clear with same-ID recreation during unmute. Old resources close without cancelling the replacement record. The existing browser capture implementation and service authority are unchanged.

Browser testing found focus loss when Start, Pause, Resume or Retry disabled/removed the invoked button. The component now moves focus to its stable status only for that action when needed, consumes the action's focus intent, and preserves focus the person has moved elsewhere. It performs no mount or unrelated-snapshot autofocus. This is tested keyboard behavior, not screen-reader acceptance.
