# P5 asynchronous lifecycle preparation — 26 October 2026

This is offline developer preparation, not a live voice implementation or device acceptance. Participant AI and voice remain off. No application route imports the new controller. A browser capture adapter is prepared but is not imported by an application route. No live provider adapter, approval grant, paid connection or model choice is introduced.

`service/voice-lifecycle.ts` coordinates injected admission, capture, connection and playback resources around the existing `MockVoiceLifecycle` transcript/segment model. The shared conversation service remains the only context and source authority; the controller neither builds provider requests nor changes saved conversation content.

The controller requires deliberate start or explicit Resume, revalidates admission before connection and activation, and preserves independent closure evidence for four resources. Pause remains unconfirmed while acquisition is pending, even if an AbortSignal was sent. Late handles are closed; failed handles remain reachable for an explicit cleanup retry. Resume cannot create another session until the previous resources and pending input changes are settled. Network recovery does not reconnect. Connection-loss events are bound to their exact attempt identity and cannot close a resumed session or change an intentional Finish talking into Pause. Type instead and Finish talking close resources while retaining the thread identity for the existing text service.

Mute changes input only. Stop answer, interruption and preference-off invalidate old output through the existing model, cancel pending shared-service work through a supplied callback, and request playback/queue cancellation. A failed playback stop closes the session. Played segments remain distinguishable from unheard cancelled segments. Private-practice assurance is available only after confirmed Pause and complete cleanup.

The port contracts require initially suppressed capture; explicit terminal resource closure; independent playback and connection cleanup; and a server-owned revalidatable admission lease. An adapter that throws during partial acquisition must clean those resources itself or return their handles for controller cleanup. An unavailable capture may carry a partial handle. Admission must not itself open a paid connection. Production wiring must retain separately approved budgets, identity, expiry, dispatch accounting and provider termination evidence; this module supplies none of that authority.

The browser adapter uses an explicitly supplied secure-context/mediaDevices environment and requests audio without video only when invoked. It initially disables input, retains ownership of tracks removed from the stream, distinguishes input suppression from track termination, checks ended state after stopping, and retains failed handles for retry. An unresolved browser permission request is not treated as cancelled merely because its AbortSignal fired. It performs no recording, storage, transcription or provider request. API basis: [W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/), including track stop semantics, mutable stream membership and unresolved permission requests. Physical microphone state is not inferred from mocked browser objects.
